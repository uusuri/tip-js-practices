## Реализация

### HTTP-клиент

Перенесены buildUrl, ApiError и обработка ответов ПР5. Добавлены методы GET, POST, PATCH, DELETE с нормализацией регистра. Неизвестный метод и body у GET отклоняются до сети. При наличии тела выполняется JSON.stringify и добавляется Content-Type: application/json. Без тела этот заголовок не добавляется. Accept отправляется всегда. Ответ 204 преобразуется в null до попытки разбора JSON. Сохранены отдельные виды http, network, invalid-response, timeout, aborted и внешний AbortSignal.

### Предметный API

`task-api.js` реализует getTasks, getTaskById, getCategories, loadInitialData, createTask, updateTask, setTaskCompleted, deleteTask и resetDemoData. Последний аргумент передаёт signal. GET-операции сохраняют валидацию фильтров и ответов ПР5. Полученная после POST/PATCH задача также проверяется по схеме. DELETE требует null, reset — подтверждение reset=true и корректный total.

### Форма и представление

`form-validation.js` проверяет название длиной 1–100 после trim, допустимый приоритет и существование числового categoryId в загруженных категориях. Ошибки привязаны к полям. `task-view.js` создаёт карточки с названием, статусом, приоритетом, категорией и действиями toggle/edit/delete. Данные выводятся через textContent; повторный renderTaskList заменяет список через replaceChildren.

### Контроллер и состояния

`app-controller.js` хранит последний ответ задач, категории, фильтры и editingId. Он не обращается к document и не вызывает fetch напрямую. DOM-адаптер и точка входа предоставлены преподавателем и не изменялись.

Во время запроса устанавливается loading, после ответа — ready или empty. При ошибке устанавливается error с кнопкой повтора. Если категории ещё не получены, повтор снова вызывает loadInitialData, а не только getTasks. Пустой результат очищает старые карточки и показывает total=0.

### Изменение данных

Создание, редактирование, статус, удаление и reset проходят через общую внутреннюю функцию: блокировка действий → мутация API → повторный GET с текущими фильтрами → разблокировка. Повторная отправка во время незавершённой мутации игнорируется. Ошибочная мутация не заменяет уже полученные данные и сохраняет форму. После подтверждённого сохранения форма возвращается в режим создания.

id назначает сервер. completed не передаётся при создании и не сбрасывается при редактировании. Массив задач в браузере является снимком API; localStorage для него не используется. Данные сохраняются между обновлениями страницы, пока работает текущий экземпляр сервера.

### Защита от устаревшего ответа

Новая загрузка отменяет предыдущую через AbortController. Дополнительно каждый запрос получает номер; результат применяется только при совпадении с последним номером. Поэтому поздний ответ не меняет новый фильтр даже при источнике, который не сразу реагирует на signal. Отмена не показывается как пользовательская ошибка. destroy отменяет текущие операции и запрещает последующее обновление представления.

```js
await waitFor(() => doc.querySelector('[data-task-id="35"]'), "Задача не появилась");
```

В исходном варианте в этом месте использовался requireNode, который сразу выбрасывал ошибку при отсутствии карточки. До завершения POST и повторного GET её отсутствие нормально. Теперь querySelector возвращает null, и существующая waitFor продолжает опрос в пределах исходных 5 секунд. Ожидаемые данные и остальные проверки не менялись. Исходная копия преподавателя в папке заданий сохранена без этой правки. До исправления браузерный прогон дал 13/14, после — 14/14.

## Ответы на контрольные вопросы

1. fetch не отклоняет Promise при 404, потому что HTTP-ответ получен. Ошибочный статус определяется через response.ok/status.
2. У 204 нет тела; response.json() пытался бы разобрать пустую строку. Общий клиент возвращает null.
3. empty означает успешный запрос без результатов, error — неуспешную загрузку.
4. Предыдущий запрос отменяется, чтобы его ответ не перезаписал результат нового фильтра. Проверка номера загрузки дополнительно защищает от позднего ответа.
5. После мутации список запрашивается заново, чтобы показать подтверждённое сервером состояние с актуальными фильтрами и назначенным сервером id.
