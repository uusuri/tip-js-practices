## Отладка и клавиатура

Поставлены настоящие точки останова Chromium через DevTools Protocol в `handleFormSubmit`: после чтения FormData, после валидации, после сервисной операции и после saveTasks. Для добавления 90 зафиксированы:

```json
{
  "draft": {
    "id": "90",
    "title": "  Документировать отладку  ",
    "priority": "high"
  },
  "normalized": {
    "ok": true,
    "value": {
      "id": 90,
      "title": "Документировать отладку",
      "priority": "high"
    }
  },
  "service": {
    "ok": true,
    "newTask": {
      "id": 90,
      "title": "Документировать отладку",
      "completed": false,
      "priority": "high"
    }
  },
  "saved": {
    "ok": true
  }
}
```

В storage записалась оболочка `{ "version": 1, "tasks": [...] }` с задачей 90. Для повторного id=4 получено `ok=false`, ошибка id; до сервиса и записи выполнение не дошло, JSON остался прежним. Enter в поле названия создал задачу без перезагрузки. Enter и Space на переключателе статуса изменили completed и вернули фокус на новую кнопку той же задачи.

## Вывод

Форма поддерживает создание и редактирование с отдельной проверкой данных. Успешные операции сохраняются, а повреждённые или недоступные данные обрабатываются через fallback и предупреждение. Сервис, валидация, хранение и представление разделены.
